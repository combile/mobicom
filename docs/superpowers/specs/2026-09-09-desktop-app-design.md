# 데스크톱 앱 (1단계: 셸과 알림)

랩 서버에서 도는 Mobi:ON을 데스크톱 앱으로 감싼다. 목표는 **채팅을 보고
있지 않아도 알림이 오는 것**이다. 지금은 브라우저 탭을 닫으면 새 메시지도,
나를 부른 멘션도 다음에 열어볼 때까지 모른다.

## Nextron을 쓰지 않는 이유

Nextron은 Next.js를 static export해서 Electron에 넣는다. 이 앱은 export하면
남는 게 없다.

| 지금 쓰는 것 | static export 후 |
|---|---|
| API 라우트 25개+ (`/api/mobion/**`) | 전부 사라짐 |
| Postgres 직접 연결 (`pg` 풀) | 서버 전용, 클라이언트에서 불가 |
| Huly WebSocket (`@hcengineering/api-client`) | 서버에서 연결 중 |
| 세션 쿠키 (`cookies()`) | 서버 함수 |

옮기려면 백엔드를 별도 서버로 떼고 프론트를 전부 클라이언트 렌더로 다시
짜야 한다. 그것은 데스크톱 앱을 만드는 일이 아니라 앱을 다시 만드는 일이다.

대신 **Electron 셸이 랩 서버를 띄우고 알림만 네이티브로 받는다.** Slack,
Discord, Notion 데스크톱 앱이 모두 이 구조다. 결정적으로 알림에 필요한
배관이 이미 있다 — `/api/mobion/chat/stream`이 SSE로 새 메시지를 밀어주고
있어서, Electron은 그걸 듣고 OS 알림을 띄우기만 하면 된다.

## 알림을 누가 듣는가

세 가지가 가능했고 첫 번째를 택했다.

**A. 웹앱이 알리고 Electron은 띄우기만 (채택)**
이미 `MobiOnContent`가 SSE를 듣고 있으므로, 거기서 브릿지를 호출한다.
Electron 코드는 창·트레이·알림뿐이고, 웹앱에는 "브릿지가 있으면 알림"
몇 줄만 들어간다. 브라우저에서는 브릿지가 없어 아무 일도 일어나지 않는다.
연결은 하나로 유지된다.

**B. 메인 프로세스가 SSE를 따로 연결**
웹앱을 한 줄도 안 고쳐도 되지만 연결이 둘로 늘어난다. 같은 계정이 두 번
접속한 것으로 잡히고 읽음 처리가 어긋날 여지가 생긴다.

**C. 웹 표준 Notification만**
Electron 없이 가능하지만 탭을 닫으면 끝이고 트레이도 배지도 없다.

## 창과 트레이

닫기가 종료가 아니다. X를 누르면 창이 숨고 트레이(macOS는 메뉴바)에 남는다.
진짜 종료는 트레이 메뉴나 `Cmd+Q` / `Alt+F4`다.

이것은 취향이 아니라 **알림의 전제조건**이다. 렌더러가 살아 있어야 SSE
연결이 유지되고, 그래야 백그라운드에서 알림이 온다. 창을 destroy하면
스트림도 함께 끊긴다.

- 트레이 아이콘 클릭 → 창 복귀 (이미 떠 있으면 포커스)
- 트레이 메뉴: 열기 / 알림 끄기 / 종료
- 안 읽음 개수를 macOS는 독 배지로, Windows는 작업표시줄 오버레이로 표시

## 알림 조건

Discord는 서버·채널마다 설정을 두지만 다섯 명짜리 랩에는 과하다. 셋으로
줄인다.

| 종류 | 기본값 | 끌 수 있나 |
|---|---|---|
| 나를 멘션한 메시지 | 켜짐 | 아니오 |
| 그 외 새 메시지 | 켜짐 | 예 |
| 나에게 배정된 태스크 | 켜짐 | 예 |

**보고 있는 채널의 메시지는 알리지 않는다.** 창이 떠 있고(`isFocused`) 그
채널이 열려 있으면 이미 읽고 있는 것이라, 알림은 방해일 뿐이다.

**자기가 보낸 메시지도 알리지 않는다.** SSE는 발신자에게도 델타를 보내므로
명시적으로 걸러야 한다.

설정은 `app.getPath("userData")` 아래 `settings.json`에 둔다. 서버가 아니라
기기에 두는 이유는 이것이 "이 컴퓨터에서 알림을 받을지"에 대한 답이기
때문이다 — 같은 사람이 랩 PC에서는 받고 집 노트북에서는 안 받고 싶을 수
있고, 웹으로 접속할 때는 해당 사항이 없다.

트레이 메뉴의 **"알림 끄기"는 위 셋을 한꺼번에 덮는 스위치**다. 멘션까지
포함해 전부 멈춘다 — 발표 중이거나 회의 중일 때 필요한 것은 종류별 조정이
아니라 하나의 스위치다. 종류별 설정은 그대로 남아 있다가 다시 켜면 복원된다.

## 알림 클릭

창을 띄우고 해당 채널로 이동한다. SSE 메시지에 `channelId`가 실려 오므로
그대로 쓴다. 이동은 이미 있는 `setActiveChannelId`를 부르는 것이라, 새로
만들 화면 전환 로직이 없다.

## 구성 요소

```
desktop/                  ← 새 폴더. 웹앱 빌드와 섞이지 않는다
  main.ts                 창 수명, 트레이, 알림, 배지
  preload.ts              window.mobion 브릿지
  package.json            electron, electron-builder
  build/                  아이콘
```

**main.ts** — `BrowserWindow`를 만들어 서버 주소를 로드한다. `close`
이벤트를 가로채 숨기고, 트레이를 만들고, IPC로 받은 알림 요청을
`new Notification()`으로 띄우고, 배지 개수를 갱신한다.

**preload.ts** — `contextBridge.exposeInMainWorld("mobion", { notify, setBadge })`.
`contextIsolation`은 켠 채로 둔다. 원격 페이지를 로드하는 앱에서 이것을 끄면
그 페이지의 스크립트가 Node에 닿는다.

**웹앱 변경** — `MobiOnContent`의 `delta` 핸들러에 조건부 호출 한 덩어리.
브릿지가 없으면(브라우저) 아무 일도 없다.

## 데이터 흐름

```
Huly tx → /chat/stream (SSE) → 렌더러 delta 핸들러
                                   ↓ 알릴 만한가?
                                   ↓ (내가 보낸 것 아님 + 보고 있는 채널 아님)
                            window.mobion.notify({ title, body, channelId })
                                   ↓ IPC
                            main.ts → new Notification()
                                   ↓ 클릭
                            창 복귀 + IPC로 channelId 전달 → setActiveChannelId
```

## 로그인 유지

세션 쿠키를 Electron의 기본 파티션에 저장한다. 이 파티션은 앱을 껐다 켜도
쿠키를 유지하므로, 한 번 로그인하면 계속 쓴다. 쿠키의 만료는 서버가 정한
대로 따른다 — 앱이 따로 연장하지 않는다.

## 서버 주소

랩 서버가 고정 IP라 `http://203.230.103.35:3300`을 기본값으로 두되,
`app.getPath("userData")` 아래 설정 파일로 바꿀 수 있게 한다. 포트가 바뀌거나
집에서 다른 주소로 붙을 때 앱을 다시 빌드하지 않아도 되도록.

## 에러 처리

**서버에 못 붙을 때** — 흰 화면 대신 "랩 서버에 연결할 수 없습니다" 화면과
다시 시도 버튼을 보여준다. `did-fail-load`로 잡는다. 랩 서버는 재부팅으로
꺼져 있는 일이 실제로 있었으므로, 이 화면은 예외가 아니라 정상 경로다.

**알림 권한이 거부됐을 때** — macOS는 시스템 설정에서 막을 수 있다. 앱은
조용히 실패하지 말고 트레이 메뉴에 상태를 표시한다.

**SSE가 끊겼을 때** — 웹앱에 이미 지수 백오프 재연결이 있다. 그동안 온
메시지는 재연결 시 스냅샷으로 채워지지만 **알림은 가지 않는다.** 끊긴 사이의
알림을 소급해 띄우면 복귀할 때마다 알림이 쏟아진다.

## 테스트

Electron 앱은 자동 테스트를 붙이는 비용이 크다. 대신 손으로 확인할 목록을
문서로 남긴다.

- 창을 닫아도 트레이에 남고 알림이 계속 오는가
- 보고 있는 채널의 메시지는 알리지 않는가
- 내가 보낸 메시지는 알리지 않는가
- 멘션 알림은 "그 외 메시지"를 꺼도 오는가
- 알림을 클릭하면 그 채널이 열리는가
- 앱을 껐다 켜도 로그인이 유지되는가
- 서버가 꺼져 있을 때 안내 화면이 뜨는가
- 배지 숫자가 안 읽음과 맞는가

알림 조건 판정(`shouldNotify`)은 순수 함수로 분리해 `assert` 기반 자체
점검을 붙인다 — `mobion-mentions.ts`가 하는 방식과 같다. 조건이 네 개
겹치는 자리이고, 잘못되면 알림이 안 오거나 쏟아진다.

## 빌드와 배포

`electron-builder`로 macOS `.dmg`와 Windows `.exe`를 만든다.

코드 서명은 유료 인증서가 필요해 1단계에서는 하지 않는다. 첫 실행 때
경고가 뜨지만(macOS는 우클릭 → 열기, Windows는 "추가 정보 → 실행") 랩 안에서
나눠 쓰는 데는 문제가 없다. 자동 업데이트도 서명이 전제라 함께 미룬다 —
새 버전은 파일로 전달한다.

## 이 문서의 범위 밖

**오프라인 읽기(2단계)** — 서버가 꺼져 있거나 랩 밖에 있을 때도 최근 대화를
읽는 것. 로컬 캐시와 동기화 충돌 처리가 붙는 별개 작업이고, 1단계가 서야
의미가 있다.

**React Native** — 모바일은 셸로 감쌀 수 없다. 화면을 새로 짜야 하므로 웹앱과
코드를 공유하는 지점이 API뿐이다. 별도 설계가 필요하다.

**전역 단축키, 화면 공유, 음성** — Discord에는 있지만 이 앱이 하는 일이
아니다.
