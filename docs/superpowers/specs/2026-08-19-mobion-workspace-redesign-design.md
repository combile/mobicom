## ① IA 통합

### 문제

프로젝트 관리가 `/tasks`라는 별도 페이지에 있어, 대화와 일감 사이를 오갈 때마다 페이지가 바뀌었다. 두 화면이 사실상 같은 워크스페이스인데 라우트가 갈라져 있었다.

### 구조

`/mobion` 한 라우트 안에서 좌측 아이콘 레일로 모드를 바꾼다.

```
Layout
├── IconRail (56px)         채팅 / 프로젝트 전환
├── mode === "chat"         Sidebar(채널·DM) + Main(메시지·입력)
└── mode === "projects"     ProjectSidebarList + ProjectDetailView
```

777줄이던 `TasksContent.tsx`를 셋으로 나눴다.

| 파일 | 역할 |
|---|---|
| `src/lib/use-tasks-data.ts` | 프로젝트·마일스톤·태스크 상태와 요청 전부 |
| `src/components/ProjectSidebarList.tsx` | 프로젝트 목록 + 생성 모달 |
| `src/components/ProjectDetailView.tsx` | 마일스톤·태스크 본문 + 생성 모달 2개 |
| `src/components/modal-styles.ts` | 생성 모달 공용 스타일 |

두 컴포넌트는 훅이 돌려준 객체를 `data` prop 하나로 받는다. 상태를 개별 prop으로 내리면 스무 개가 넘어가고, 두 컴포넌트가 `selectedProjectId`를 공유해야 해서 훅을 각자 부를 수도 없다.

### 판단

**채팅과 프로젝트를 한 컴포넌트에 둔다.** SSE 연결이 `MobiOnContent` 최상위 `useEffect`에 있어, 모드를 컴포넌트 경계로 가르면 전환할 때마다 연결이 끊긴다.

**프로젝트 요청은 `enabled` 플래그로 막는다.** 채팅만 쓰는 사용자에게 프로젝트 API 요청이 나가지 않는다.

**모드 전환은 언마운트 방식이다.** `display: none`으로 숨기는 방식도 검토했으나, 래퍼가 하나 더 생겨 `Layout`의 flex 직계 자식 관계가 깨지고, 숨겨진 동안 `scrollHeight`가 0이라 스크롤 복원이 무력화된다.

### 유실 전 리뷰가 잡았던 문제

재구현에서는 사후 수정이 아니라 처음부터 피했다.

**모달이 244px로 잘리던 문제.** `Sidebar`와 `Main`이 `backdrop-filter`를 쓰는데, 이 속성은 자손 `position: fixed` 요소의 containing block을 만든다. 모달을 패널 안에 두면 뷰포트가 아니라 패널 너비에 갇힌다. 생성 모달을 전부 `createPortal(..., document.body)`로 렌더해 해결했다. 같은 이유를 `modal-styles.ts` 주석에 남겨, 다음에 모달을 추가하는 사람이 같은 실수를 반복하지 않게 했다.

**모드 전환 후 채팅 스크롤이 맨 위로 가던 문제.** 자동 스크롤 `useEffect`의 deps가 `[messages, activeChannelId]`뿐이라, 재마운트돼도 값이 그대로면 실행되지 않았다. deps에 `mode`를 넣었다.

**프로젝트 목록 로드 실패가 조용히 묻히던 문제.** 실패 시 빈 목록만 보였다. `loadError`를 사이드바에 표시한다.

**레일 추가로 패널이 좁아지던 문제.** `Layout`의 `max-width`를 1100px에서 1156px로 올려 레일 56px을 흡수했다. 기존 값 기준으로 잡힌 채팅·프로젝트 패널 폭이 그대로 유지된다.

### 라우팅

`/tasks`는 `/mobion`으로 리다이렉트만 남긴다. 헤더 nav에서 "태스크" 링크를 뺐다.

### 검증

타입체크와 프로덕션 빌드 통과. 브라우저 실동작 확인은 미완료.

## ② 생성 UI

**버튼**은 위치에 따라 다르게 간다. 사이드바의 "프로젝트 추가"는 점선 상자를 없애고 옆 프로젝트 항목과 같은 행 스타일로 녹였다(평소 회색, hover 시 같은 배경 + 강조색). 섹션 헤더의 "마일스톤/태스크 추가"는 목록 항목이 아니라 별개 동작이므로 tonal fill(`rgba(0, 181, 255, 0.12)`) pill로 구분한다. 헤더 버튼까지 행 스타일로 녹이면 아래 목록의 한 줄로 오인된다.

**애니메이션**은 생성 모달 4개(프로젝트·마일스톤·태스크·채널)를 공용 훅 `src/lib/use-modal-enter-animation.ts`로 통일했다. GSAP은 `Header.tsx`가 이미 쓰고 있어 의존성 추가가 없다.

| 대상 | 시작 | 끝 | 시간 |
|---|---|---|---|
| overlay | opacity 0 | opacity 1 | 0.15s |
| card | opacity 0, scale 0.96, y 8px | opacity 1, scale 1, y 0 | 0.18s, power2.out |

퇴장 애니메이션은 범위 밖이다. 언마운트를 지연시키는 상태가 추가로 필요하다.

**입력 포커스** 스타일은 공용 `Field`에 한 번만 넣었다. 네 모달이 같은 `Field`를 쓰므로 규칙 하나가 전부를 덮는다. 테두리 `#00b5ff` + `0 0 0 3px rgba(0, 181, 255, 0.15)` 글로우이며, `outline: none`으로 기본 표시를 꺼둔 상태라 이 스타일이 없으면 포커스 위치를 알 수 없다.

**모듈 스코프가 핵심이다.** 모달을 부모 컴포넌트 안에 인라인으로 두면 부모가 리렌더될 때마다 모달이 새 컴포넌트 타입이 되어 React가 재마운트하고, 입력 중이던 포커스가 풀린다. 네 모달을 전부 모듈 스코프 함수로 뺐다. 같은 구조 덕분에 모달이 열릴 때 마운트되므로 `useGSAP`도 제 시점에 걸린다.

`MobiOnContent`가 따로 갖고 있던 모달 스타일 정의는 공용 모듈로 교체해 제거했다. 채널 모달은 훅으로 상태를 묶을 수 없어 props 20개를 받는데, 상태가 `MobiOnContent`의 채팅 로직과 얽혀 있어 별도 훅으로 떼면 오히려 경계가 흐려진다.

### 검증

타입체크와 프로덕션 빌드 통과. 브라우저 실동작 확인은 미완료 — 특히 **모달 진입 애니메이션과 입력 포커스 유지**는 실제로 눈으로 봐야 확인되는 항목이다.
